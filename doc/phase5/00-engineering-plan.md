# 阶段五工程化计划

状态：进行中（2026-10-04）。范围：T-31～T-33。

## 1. 执行顺序

| 顺序 | 任务 | 产出 | 当前状态 |
| --- | --- | --- | --- |
| 1 | T-31 脚本闭环 | `build.ps1`、`test.ps1`、`release.ps1` | 已实现，发布冒烟通过 |
| 2 | T-32 CI | `.github/workflows/ci.yml` | 已实现，待 Windows runner 验证 |
| 3 | T-33 统一门禁 | 质量门禁脚本、扫描报告和失败退出码 | 已实现，本机通过，待 runner 验证 |

## 2. T-31 验收标准

- `build.ps1` 固定使用 Go 1.26.0，产出带版本、提交和构建时间的 EXE；
- `test.ps1` 执行 gofmt、vet、全量测试和覆盖率门禁，任一失败返回非零；
- `release.ps1` 调用同一构建逻辑，生成 EXE、SHA256 校验文件和构建元数据；
- 脚本恢复调用前的 `PATH`、`CGO_ENABLED` 和 `GOTOOLCHAIN`；
- 发布脚本不创建 tag、不上传产物、不修改系统配置。

## 3. T-32 计划

Windows runner 使用 Go 1.26.0，按顺序执行：

1. 检查 `gofmt -l`；
2. 执行 `go vet ./...`；
3. 调用 `scripts/test.ps1` 并保留覆盖率产物；
4. 执行 amd64 和 arm64 交叉编译；
5. 调用 `scripts/build.ps1` 验证版本注入。

CI 只验证可重复的构建与静态门禁。网络、权限、UNC、企业策略和其他 Windows 版本仍由阶段四的真机验收矩阵管理。

## 4. T-33 计划

统一入口需要报告每项门禁的命令、退出码和产物路径，覆盖格式、vet、测试/覆盖率、交叉编译、运行时禁用 API 与外部进程扫描。红线扫描继续区分生产代码、测试、工具和文档，允许的报告写入与控制台恢复调用需要人工复核。

## 5. 风险与限制

- Go 1.26.0 未预装时，离线环境不能自动下载工具链；脚本应直接失败并说明安装要求。
- CI 的交叉编译成功不等于 arm64 真机支持。
- 质量门禁不能取代阶段四未覆盖的标准用户和隔离环境验收。
