# 阶段四验收计划

状态：已完成（2026-10-04，带明确环境限制）。范围：WBS 的 T-28 集成验收、T-29 场景演练、T-30 红线复核；本机可执行项目已完成，未取得的环境保持未覆盖。

## 2. T-28 集成验收

| 编号 | 操作 | 判定标准 |
| --- | --- | --- |
| I-01 | `whoami`、`systeminfo` 与报告对照 | 主机/账户/版本/架构匹配；开机时间记录近似误差 |
| I-02 | `ipconfig /all`、`Get-NetAdapter -IncludeHidden` 与报告逐接口核对 | GUID/索引关联；名称、MAC、IP/掩码、网关、DNS、DHCP、管理和链路状态一致；差异需解释，不要求清单数量相等 |
| I-03 | 同一 IPv4 网关运行 `ping -n 4`，比较本工具 | 比较目标、成功/失败与合理延迟范围，不要求两次动态 RTT 完全相同；权限拒绝与网络无响应分别记录 |
| I-04 | 读取报告字节并在记事本打开 | 前三字节 EF BB BF，换行为 CRLF，无 ANSI 控制序列，三层中文可读，错误原文可追溯 |
| I-05 | 真实 GBK/UTF-8 控制台、NO_COLOR、stdout/stderr 重定向 | 正常中文或明确 ASCII 降级；文件报告中文；退出后共享代码页/模式恢复。代码页演练仅在可恢复的专用控制台执行 |
| I-06 | 正常诊断、已存在严重异常环境、非法参数/报告不可写 | 0/1/2 语义正确；未能获取严重异常环境时保留模拟证据但不得勾选真实退出 1 |
| I-07 | 空目录仅复制 EXE 运行 | 无额外 DLL/配置/Go/PowerShell 需求，仅产生报告及必要目录 |

资源精度：内存/磁盘按相同字段、单位与时刻对照，WBS 要求误差 <2%；CPU 应按相同一秒窗口及系统总 CPU 口径比较，避免拿错时刻的任务管理器瞬时值证明精度。磁盘区分调用者可用空间和卷总空闲，内存区分物理使用量与提交量。无法同步测量时先记录方法限制，不宣布精度通过。

## 3. 非功能测量

- 耗时：同一候选 EXE 连续十次，记录每次进程开始、首行、结束、退出码及报告路径；分别报告平均和最大。完整诊断目标 ≤30 秒、典型 ≤15 秒；首行 ≤3 秒。超限单次不能被平均值掩盖，异常同步调用单列。
- 内存：采样进程工作集峰值，记录采样间隔；同时保留私有字节作参考，不能混用口径。目标 ≤50 MB，明确 MB 换算。短周期采样可能遗漏尖峰，必要时结合系统观测。
- 体积：记录字节数和换算，EXE ≤15 MB。
- 可复现：同机连续三次，比对接口排序、规则身份与静态字段；时间、动态资源、RTT、文件名允许变化，解释动态变化引起的告警。
- 健壮性：采集失败不能伪造正常值；跳过/不完整探测不能当作全部失败；保留其他有效结果。报告/控制台写入失败可返回 2。

## 4. T-30 红线复核

检查生产源码及实际调用关系，排除测试、工具和文档中的名称引用后人工判定：

```powershell
rg -n 'RegSetValue|RegCreateKey|SetIpInterfaceEntry|CreateService|InternetOpen|os/exec|exec\.Command|CreateProcess|ShellExecute|powershell|wmic|wscript|cscript|cmd\.exe' internal cmd -g '*.go' -g '!**/*_test.go'
rg -n 'WriteFile|OpenFile|Mkdir|Remove|SetConsole|Dial|Lookup|IcmpSend' internal cmd -g '*.go' -g '!**/*_test.go'
```

搜索无匹配时 rg 返回 1 是正常结果；输出是候选调用清单，不是最终结论。核对报告目录/排他创建/失败清理、stdout/stderr、临时控制台模式恢复属于允许行为；确认无配置写入、修复、上报、驻留、GUI 或外部进程。DLL 导入表只能辅助核对，不能证明不存在进程启动或动态加载。

## 5. 出口与缺陷处理

1. 每项结果使用通过、失败、阻塞、未覆盖四种状态；模拟/真机/编译证据分开。
2. 每个通过项关联代码/EXE 身份、环境、步骤、原始结果或报告路径。
3. 失败先记录复现和期望，修复后补回归并复测相关场景及质量门禁。
4. 场景全量登记；无法构造的场景说明环境需求与替代证据，不能默认为通过。
5. 无已确认未解决的阻断缺陷；兼容矩阵未覆盖项必须形成交付限制。阶段四可以以“完整验收”或“带明确限制的收口”结束，并在阶段入口和结果台账中保持一致。
6. 更新 WBS T-28～T-30 和阶段四结果报告；阶段五 CI/发布流水线仍单独推进。

本阶段按第二种出口收口：本机可执行验收通过，标准用户、隔离破坏性场景、其他 Windows/Server、arm64 真机等环境未覆盖；相关限制已写入 `README.md` 和 `01-results.md`。后续取得新环境时追加验收记录，不将当前限制改写为历史通过。
