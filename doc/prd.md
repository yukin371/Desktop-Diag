# Desktop-Diag桌面运维一键诊断工具产品需求文档（PRD）

## 1. 项目概述
### 1.1 产品名称
Desktop-Diag 桌面运维一键诊断工具
### 1.2 产品定位
一款轻量、无外部依赖、企业合规、只读安全的Windows桌面故障智能诊断工具，专注服务企业IT桌面运维场景。产品严格遵循只诊断、不主动修复、不篡改系统配置的核心原则，仅做数据采集、故障判定、告警提示与报告输出。
产品核心解决行业普遍痛点：传统人工命令排查重复冗余、新人运维排错标准不统一、故障漏判误判率高、断网环境故障难以定位、运维排查无标准化留存报告、故障复盘与溯源困难等问题，实现桌面运维排错流程标准化、智能化、轻量化。
### 1.3 产品核心差异化（核心面试亮点）
系统自带ipconfig、ping、BAT/PS脚本等原生工具，仅能输出原始文本信息，无数据解析、故障判断能力，完全依赖人工肉眼分析，效率极低、标准不一。
本产品绝非简单的系统命令封装，核心价值是运维排错逻辑自动化，具备四大核心能力：结构化解析原始运维数据、全自动智能故障判定、精准故障告警、标准化可视化诊断报告输出，彻底替代人工判断环节，统一企业桌面运维排错标准。
### 1.4 技术选型与产品形态
- 开发语言：Go（轻量高效、编译单文件、运行资源占用低）
- 交付形态：独立单文件EXE，无外部依赖、无需安装、无需额外运行库，开箱即用
- 界面形态：控制台模式，优先保障轻量属性、企业合规性、不被EDR/组策略拦截
- 输出形式：控制台实时打印检测日志 + 本地结构化TXT标准化诊断报告
- 运行说明：程序运行依赖Windows原生WMI、注册表、PowerShell系统组件，无第三方外部依赖，仅做本地数据读取，无恶意行为；存在被部分安全软件误报的可能性，属于正常兼容问题
## 2. 业务背景与痛点分析
### 2.1 现有桌面运维核心痛点
1. 人工运维效率极低：传统排错需要运维人员手动输入多组命令、肉眼比对数据、人工判断故障，重复劳动量大，单次排错耗时久。
2. 新人排错不标准、漏判率高：新人运维经验匮乏，极易忽略169.254无效IP、空网关、DNS配置异常、磁盘空间爆满、内存过载等高频隐性故障。
3. 断网环境无法运维：终端故障时常伴随断网，无法下载第三方运维工具、安装运维软件，无可用排错手段。
4. 企业环境限制严格：企业普遍禁用U盘、移动硬盘等外接设备，外来程序拦截策略严格，传统便携运维工具无法落地。
5. 传统脚本兼容性差：BAT、PowerShell原生脚本易被EDR、企业组策略拦截，仅能输出原始文本，无结构化数据与智能判错能力。
6. 无标准化运维台账：人工排查无统一故障报告，故障交接、问题复盘、责任溯源、问题统计均无数据支撑。
### 2.2 现有同类产品缺陷（竞品分析）
1. 系统自带疑难解答：黑盒运行逻辑，无法查看排查细节、无数据留存，企业域环境中常被策略禁用，无法适配企业运维场景。
2. BAT/PowerShell原生脚本：仅输出原始文本数据，无智能故障判断、无告警提示，易被安全策略拦截，代码零散不可维护，无标准化报告。
3. Sysinternals工具集：工具分散独立，需要人工逐个调用、手动分析数据，无一键整合排查能力，无统一诊断报告。
4. 商用RMM运维平台：需要安装客户端程序、部署成本高、大多收费，断网环境失效，程序臃肿占用资源大，轻量化中小企业无法适配。
### 2.3 本产品核心解决问题
重构传统桌面运维排错模式，将人工敲命令、人工读数据、人工判故障的低效模式，升级为程序全自动检测、智能故障判定、精准告警提示、一键生成标准化报告的标准化运维模式，低成本、高效率解决企业桌面终端各类常规故障排查难题。
## 3. 用户角色与使用场景、合规设计
### 3.1 目标用户
企业IT助理、桌面运维工程师、中小企业运维新人、零基础运维从业人员。
### 3.2 核心使用场景
1. 终端常规故障排查：员工电脑出现网络断连、网页打不开、网络卡顿、系统运行缓慢等问题时，快速定位故障原因。
2. 远程协助排查（最高频场景）：无U盘、无设备接触，依托企业内网共享目录直接运行，适配远程运维场景，突破外接设备限制。
3. 故障复盘与台账留存：批量终端故障排查后，通过标准化报告留存数据，用于故障统计、问题复盘、运维台账归档。
4. 新人标准化培训：统一排错流程、统一故障判断标准，降低新人运维学习门槛，减少人为失误。
### 3.3 企业合规核心设计（面试高分重点）
产品核心合规准则：仅本地写入诊断报告，不修改任何系统配置，全程安全可控，适配企业终端安全规范。
1. 部署合规：不依赖U盘等外接设备运行，依托企业内网共享目录部署运行，规避外接设备安全风险。
2. 操作合规：不写入系统关键注册表、不修改网络IP/DNS/网卡配置、不篡改系统任何原生配置。
3. 风险合规：默认模式仅诊断、不修复，杜绝自动修复导致的故障扩大、系统异常等风险。
4. 形态合规：单文件EXE程序，无安装包、无捆绑插件、无后台驻留、无主动网络数据上传行为。
5. 网络合规：仅执行本地连通性探测（ping、DNS、TCP443探测），用于故障判定，全程无用户数据、诊断数据上传行为。

## 4. 产品核心设计原则
只读不写、只诊不修、轻量合规、断网可用、标准化判错、安全可控

## 5. MVP版本功能（国庆可落地Demo版，核心主推）
MVP版本主打轻量化、高价值、可落地、合规安全，不做冗余功能，完全区别于普通脚本，具备完整的产品化能力，无安全风险。

### 5.1 系统信息结构化采集（核心差异化能力）

摒弃原生命令原始文本输出，自动解析、结构化提取标准化系统与网络数据，数据格式清晰、可直接用于运维分析。
采集内容：计算机名、系统版本、系统运行时长、全量网卡列表、IP地址、子网掩码、网关、DNS、MAC地址。
全自动智能判错告警逻辑（核心价值，区别普通脚本）：
- IP地址以169.254开头 → 告警：DHCP地址获取失败，终端未获取有效内网IP
- 网关配置为空 → 告警：无网关配置，内网出口异常，无法正常联网
- DNS为空/配置异常 → 告警：DNS解析异常，网页无法正常访问

### 5.2 网络连通性智能检测（优化适配防火墙场景）

规避单一ping探测被防火墙拦截的问题，采用ICMP+TCP+DNS多重探测机制，精准判断网络故障类型。
自动执行三组探测：
1. 本机网关ICMP连通性探测（判断内网链路状态）
2. 公共DNS 223.5.5.5 DNS解析探测（判断外网解析能力）
3. 公共地址TCP 443端口连通性探测（规避ICMP被拦截导致的误判）
自动分析维度：统计网络丢包率、延迟波动，智能区分内网故障、外网故障、全断网故障，精准定位故障层级。
网络行为说明：所有网络操作仅用于本地连通性故障探测，无任何数据上传、无隐私泄露风险。

### 5.3 系统健康度检测

采集终端硬件与系统运行状态，定位系统卡顿、运行缓慢核心原因，配套智能预警机制。
检测指标：CPU实时占用率、内存使用率、剩余内存容量、C盘总容量、C盘剩余空间。
自动告警规则：
- C盘剩余空间＜10GB → 磁盘空间不足预警，提示存在系统卡顿、更新失败风险
- 内存占用率过高 → 系统内存过载预警，提示终端运行卡顿、程序闪退风险

### 5.4 标准化三层诊断报告自动生成

输出职业化、标准化结构化TXT报告，适配运维复盘、交接、溯源场景，报告分层清晰、优先级明确。
报告三层结构：
1. 第一层：异常告警汇总（核心优先级）：集中展示所有故障、预警信息，运维人员可快速定位问题，无需通读全文。
2. 第二层：结构化检测数据详情：展示所有系统、网络、硬件标准化采集数据，数据清晰规整。
3. 第三层：原始命令输出附录：保留原生命令原始数据，支持运维人员深度排错、问题溯源。
报告命名规则：diag_YYYYMMDD_HHMM.txt，按时间自动命名，方便归档管理。
### 5.5 MVP版本严格禁止能力（保障合规安全）

为坚守企业合规底线、杜绝运维风险，MVP版本坚决不做任何系统修改、数据上传、自动修复类操作：
- ❌ 不自动修改IP、DNS、网卡等网络配置
- ❌ 不重启系统服务、不修改系统注册表
- ❌ 无任何联网数据上传、数据上报行为
- ❌ 无后台驻留、无GUI弹窗、无自启动机制

### 5.6 MVP版本可选只读增强功能（不破坏核心定位）
在不修改“只诊不修、只读合规”核心定位的前提下，新增轻量化只读采集能力，丰富报告内容，提升产品价值：
1. 开机启动项只读采集：读取注册表Run/RunOnce、系统启动文件夹、任务计划、系统服务信息，标注程序发布者、运行路径，智能标记可疑启动项（无签名、异常路径、临时目录启动等）。
2. 磁盘占用只读分析：扫描系统临时文件、浏览器缓存、回收站、系统日志、更新缓存等文件占用情况，仅统计占用大小、展示明细，不执行任何删除操作。

## 6. 产品迭代规划（体现产品思维，分层落地、合规迭代）

整体迭代遵循先诊断、后建议、再可控优化的原则，严格区分只读模式与优化模式，杜绝默认修改系统的风险，保障全程合规安全。产品分为两大核心模式：诊断模式（默认只读，全程无修改）、安全优化模式（可选开启，需授权、可回滚）。

### 6.1 V1.1 功能增强版（进阶迭代）

1. 系统事件日志错误采集：识别系统报错、服务崩溃、网卡异常、程序闪退等日志信息。
2. 打印服务专项检测：检测打印服务运行状态、打印队列卡死、服务未启动等打印故障。
3. 系统进程分析：采集CPU/内存高占用Top10进程，精准定位系统卡顿源头。
4. 权限适配检测：区分普通用户/管理员权限可采集项，给出友好权限提示。
5. 启动项风险分级提示：基于只读采集数据，输出启动项安全风险评估与优化建议。
6. 磁盘垃圾占用明细展示：统计各类缓存、临时文件占用占比，给出清理优化建议。
7. 故障告警分级：区分正常、警告、严重故障三个等级，优化运维排查优先级。

### 6.2 V1.2 标准化运维版（企业落地版）

1. 系统风险项采集：扫描开机自启项、计划任务异常风险，形成标准化风险清单。
2. 可视化报告升级：支持HTML格式诊断报告，界面美观、数据可视化，适配归档展示。
3. 台账自动归档：支持报告自动保存至企业内网共享文件夹，实现批量故障台账统一管理。
4. 安全优化前置能力：新增dry-run模拟检测模式，提前展示可优化项，不直接执行操作。
5. 可控启动项优化：支持手动禁用可疑启动项，自动备份原配置，全程支持一键回滚。

### 6.3 V2.0 完整工具版（远期规划）

1. 可选轻量化GUI界面，兼顾专业控制台模式与可视化操作模式。
2. 蓝屏日志解析：自动提取系统蓝屏日志、报错代码，辅助定位系统底层故障。
3. 内置运维知识库：每条故障告警配套标准化排查步骤、解决方案，赋能新人运维。
4. 局域网批量检测：支持批量扫描内网终端状态，适配企业批量运维场景。
5. 完整安全优化模式：独立可控的优化模块，支持文件隔离清理、操作日志留存、全量回滚。
6. 版本区分：保留企业合规只读版，同时提供可选优化版本，适配不同企业安全策略。

## 7. 安全优化模块设计规范（核心合规底线）

所有系统优化、清理、修改类功能默认关闭、不默认执行，仅在用户主动开启安全优化模式、二次确认、授权管理员权限后才可执行，全程可追溯、可回滚、无不可逆风险。

### 7.1 开机自启动管理规范

- 只读采集（默认）：读取注册表HKCU/HKLM Run、RunOnce、启动文件夹、任务计划、系统服务，标注文件签名、运行路径、启动方式，标记可疑风险项。
- 可控写操作（可选）：仅支持禁用启动项，不删除任何配置；自动备份原注册表/任务计划配置，支持一键恢复；检测到域策略锁定时，主动提示“被组策略管理，无法修改”，避免强制操作报错。

### 7.2 系统文件清理规范

- 只读扫描（默认）：仅扫描%TEMP%、Windows临时目录、浏览器缓存、回收站、系统更新缓存、系统日志、缩略图缓存等目录的文件占用情况，无删除操作。
- 安全清理原则（可选）：仅清理白名单目录文件，跳过占用中文件、符号链接文件、系统关键文件、用户个人文件（文档、桌面、下载、程序目录）；默认dry-run模拟执行，展示清理清单，用户手动确认YES后再执行；所有清理文件支持隔离备份、删除清单留存、一键回滚。

## 8. 产品核心竞争优势

1. 优于系统原生命令：摆脱人工肉眼排查模式，程序自动识别故障特征、智能判定问题，无需人工数据分析。
2. 优于传统BAT/PS脚本：具备结构化数据解析、标准化运维业务逻辑、智能告警、报告归档能力，绝非简单命令封装，产品化程度高，且不易被安全策略拦截。
3. 优于商用RMM运维平台：无需安装客户端、无收费成本、断网可用、轻量无冗余，完美适配中小企业轻量化运维场景。
4. 极致企业合规性：适配企业U盘禁用、终端安全拦截策略，默认只读不篡改系统，无任何运维安全风险。
5. 运维标准化价值：统一新人排错流程与故障判定标准，彻底解决人工漏判、误判、标准不统一的行业痛点，助力企业运维规范化。
